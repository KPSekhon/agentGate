# 0003. Store signing keys as PKCS#8

Status: Accepted

## Context

The signing key is the root of trust for the whole system, so how it is stored
matters. The first implementation took a raw 32-byte Ed25519 seed as a hex
string in an environment variable.

A bare seed is just bytes. Nothing in it records which algorithm it belongs to,
no other tool can read it, and there is no structure to validate, so a truncated
or corrupted value fails deep inside key loading rather than at parse time.
Passing key material through an environment variable also leaks it into process
listings and shell history.

## Decision

Store signing keys as PKCS#8, the standard serialization for private keys, and
load them from a file path rather than an environment variable. A new
`agentgate keygen` subcommand writes the key and prints its key id and public
key.

Both PKCS#8 encodings in circulation are accepted:

- Version 2 (RFC 5958) carries the public key alongside the private key, so the
  pair can be cross-checked for consistency at load time. This is what ring
  emits and what keygen writes.
- Version 1 (RFC 5208) holds only the private key. This is what
  `openssl genpkey -algorithm ed25519` emits, and rejecting it would mean a key
  produced by the most common tool in the ecosystem could not be used.

## Consequences

- Keys are interoperable. A key generated by OpenSSL loads unchanged, verified
  by a test that builds a v1 document by hand and checks it yields the same key
  id as the equivalent raw seed.
- The file carries an algorithm identifier, so a wrong or corrupt key is
  rejected at parse time with a clear error instead of failing obscurely later.
- Key material lives in a file that can be permission-restricted rather than in
  an environment variable inherited by child processes.
- `from_seed` is kept for tests, where determinism is more useful than format
  metadata, but it is documented as the non-production path.
- The key is still a plain file on disk. Storing it in an HSM or KMS so the host
  cannot exfiltrate it remains future work.
